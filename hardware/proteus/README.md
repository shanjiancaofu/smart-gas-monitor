# Proteus 仿真说明

本目录用于存放 Proteus 仿真工程（`.pdsprj`）。工程文件需要在 Proteus 里手工搭建，本文给出搭建所需的元件、参数、接线和逐步骤的演示脚本，照着做即可，不需要再推导。

引脚分配以[硬件设计与接线说明](../schematic/)中的《智能燃气监测与自动防护系统_硬件设计与接线说明》为准，本文不重复整张引脚表，只写仿真特有的部分。

## 一、仿真能验证什么

**能验证**：采样到执行的完整链路——ADC 读数如何变成状态、状态如何驱动 LED/蜂鸣器/继电器、OLED 三个界面、两路串口的命令与应答、报警记录的写入与读回、KEY4 恢复的条件、参数保存，以及掉电后阀门锁存是否真的保留下来（这一条取决于 EEPROM 模型在仿真重启之间是否保留内容，见第六节）。

**不能验证**：MQ 传感器的预热特性与真实响应曲线、继电器接点与实物电平、HC-05 的无线链路、晶振起振、ADC 的噪声特性。这些必须在实物上确认。

## 三、MCU 属性与最小系统

双击 MCU，在属性里设置：

| 属性 | 值 | 说明 |
| --- | --- | --- |
| Program File | `stm32f103/cubemx/build/smart_gas_monitor.hex` | 先 `make -C stm32f103/cubemx` 生成 |
| Clock Frequency | **8 MHz** | 必须与固件的 HSE 一致 |

最小系统另外需要：

- **BOOT0 经 10 kΩ 下拉到 GND**，BOOT1 也下拉。BOOT0 悬空时模型可能从系统存储器启动，表现是「下载了固件但什么都不动」。
- 8 MHz 晶体接 PD0/PD1（OSC_IN/OSC_OUT），两端各一个 22 pF 到地。接上更贴近实物；Proteus 的 STM32 模型按属性里的 Clock Frequency 运行，因此即使不画晶体仿真也能跑，但**原理图必须画**。
- NRST 经 10 kΩ 上拉到 3.3 V，并接一个按键到地，方便手动复位重做演示。
- **PA8 经 10 kΩ 下拉到 GND。** 这不是仿真需要，是原理图要求：复位后到 `MX_GPIO_Init()` 之间 PA8 是浮空输入，没有这个下拉，继电器在这段窗口里状态不可控。仿真里加上它，顺带验证复位瞬间继电器确实不吸合。

## 四、三路 "MQ" 怎么模拟

Proteus 没有 MQ-4/7/8 模型。用**电位器模拟 MQ 模块的 AO 输出**，**并保留原理图里真实的 10 k/18 k 分压**——这样仿真接法和最终原理图一致，分压取值也顺便被验证了一次。

每路接法（MQ-4 为例，另两路相同）：

```text
5V ──┬── POT (1k) 两端接 5V 与 GND，中间抽头就是 MQ AO
     │
   抽头 ── R1=10k ──┬──── PA0
                    │
                  R2=18k
                    │
                   GND
```

电位器建议用 **1 kΩ** 而不是 10 kΩ：分压网络的等效负载约 28 kΩ，1 kΩ 电位器在中间位置时源阻抗只有 250 Ω，分压误差小于 1%；用 10 kΩ 时误差接近 8%，演示电压会对不上表。

### 电压与 ADC 读数的换算

固件是 12 位、右对齐，VREF 取 VDDA = 3.3 V，所以：

```text
ADC 计数 = V(AO) × 18/28 × 4095 / 3.3 ≈ V(AO) × 798
```

反过来，要凑出某个计数，电位器抽头应该调到：

| 目标 | ADC 计数 | 抽头电压 V(AO) | 分压后 V(PA0) |
| --- | --- | --- | --- |
| 洁净空气基准 | 约 640 | 0.80 V | 0.51 V |
| MQ-7 安全线（70%） | 1400 | 1.76 V | 1.13 V |
| MQ-4/MQ-8 安全线（70%） | 1680 | 2.11 V | 1.35 V |
| MQ-7 预警线（80%） | 1600 | 2.01 V | 1.29 V |
| MQ-4/MQ-8 预警线（80%） | 1920 | 2.41 V | 1.55 V |
| MQ-7 报警阈值 | 2000 | 2.51 V | 1.61 V |
| MQ-4/MQ-8 报警阈值 | 2400 | 3.01 V | 1.93 V |

演示时按这张表拧电位器即可，不必去猜计数。600～700 那个基准值对应「洁净空气」，低于任何阈值，是演示的起点。

## 五、两路串口怎么连

Proteus 没有 HC-05 模型。两路都用虚拟终端代替，**它就是手机或电脑那一侧**：

| 固件 | Proteus 接法 | 终端设置 |
| --- | --- | --- |
| USART1（USB-TTL） | PA9 → 终端 RXD，PA10 → 终端 TXD | 115200, 8-N-1 |
| USART2（HC-05） | PA2 → 终端 RXD，PA3 → 终端 TXD | **9600**, 8-N-1 |

**串口 2 的波特率必须是 9600**，与固件里 HC-05 的配置一致；设成 115200 会满屏乱码，那不是固件的 bug。

两个终端收到的是同一份内容——同一套文本协议，任一路能做的事另一路也能做。想模拟真实的上位机，可以把 USART1 换成一个 `COMPIM` 绑到电脑的 COM 口，用串口助手当上位机。

## 六、接线要点与常见坑

- **I2C 必须加上拉。** 两组 I2C 各需要在 SDA、SCL 上接 4.7 kΩ 到 3.3 V（PB6/PB7 一组，PB10/PB11 一组）。HAL 的 I2C 是开漏输出，没有上拉时总线永远拉不高，表现是「OLED 全黑、EEPROM 读写全失败、面板显示 STORE FAIL」。真实的 OLED 和 AT24C02 模块板上自带这两个电阻，Proteus 里用的是裸芯片，所以要自己加。
- **OLED 未必有模型。** 部分 Proteus 版本带 SSD1306 模型，部分没有。如果搜不到，挂一个 `I2C DEBUGGER` 在 PB6/PB7 上，能看到固件周期性向地址 0x3C 写命令和数据——这足以证明面板在被打驱动，但看不到画面。面板的实际显示效果要留到实物确认。
- **面板全黑不等于固件没跑。** `display_update()` 在 OLED 没就绪时直接返回，其余功能不受影响。判断固件是否在跑，看串口有没有应答，而不是看屏幕。
- **AT24C02 的掉电保持。** Proteus 的 EEPROM 模型在仿真运行期间保存内容，但停止仿真再启动是否保留，取决于版本和模型属性。这一条现在比过去重要：阀门锁存和阈值都寄存在这片 EEPROM 里（配置区 0x00～0x1F，第 12 字节是 lockout 标志）。**如果模型重启后回到全 1**，那么每次上电都被当作干净上电，第 2 步的自动开阀和下面的锁存演示都会变成「回到了初始状态」——这不是固件的 bug，是模型没掉电保持。做法是先实测：改一个阈值、停止仿真、重新运行，用 `CONFIG?` 看阈值还在不在。在不在，锁存演示才有意义；不在，锁存这一条只能留到实物确认。另外，配置格式这一轮升到了 **v5**（蜂鸣器时长占第 4 字节），**v4 的旧记录会被判为无效**，整份配置连同阈值和采样周期一起回落到默认值——这是有意的，新版固件不该照着一个旧布局去猜。所以升级固件之后第一次上电时，`CONFIG?` 显示默认值是正常的，不是没存住。
- **ADC 是第一个要确认的环节。** 如果上电后 OLED 直接显示 `FAULT`，通常是 Proteus 的 ADC 模型没有按预期完成转换。固件用 `HAL_ADC_PollForConversion(..., 5)` 轮询，5 ms 内没完成就判为采样失败。遇到这种情况先确认 Clock Frequency 是 8 MHz，再检查 PA0/PA1/PA4 上确实有电压。
- **蜂鸣器响一段时间后自动停**，默认 5 秒，这是设计行为，不是故障。红灯和关阀不受影响，会一直保持。响多久可以在参数页按 KEY2/3 调整，也可以用 `SET BUZZER` 从串口改，档位是 1～60 秒、`OFF`、`ALWAYS`。设成 `ALWAYS` 之后它当然不会停——那不是故障，是设置成了这样。

## 七、演示脚本

每一步都给出预期现象，对不上就查第八节。**三路电位器初始都调到 0.8 V 左右（约 640 计数）。**

### 1. 上电与预热

运行仿真。预期：

- OLED 实时页三行显示 `MQ4  640/2400`、`MQ7  640/2000`、`MQ8  640/2400`，末行 `WARMUP  CLOSED`
- 黄灯亮，绿灯灭，红灯灭，阀门指示灯灭
- 继电器不吸合（PA8 为低）
- 蜂鸣器不响
- 两个虚拟终端都没有输出

预热是 60 秒**仿真时间**。Proteus 仿真 72 MHz 的 STM32 一般慢于实时，实际等待可能明显长于 60 秒，具体取决于机器和版本。如果这一分钟影响演示节奏，可以**临时**把 `stm32f103/app/gas/gas_monitor.h` 里的 `GAS_WARMUP_MS` 改小重新编译，演示完再改回 `60000u`；交付的固件必须保持 60000。预热结束前的高浓度同样会进 ALARM 并锁存，所以改小预热不会掩盖任何报警行为。

### 2. 预热结束，自动开阀

预期：状态变成 `NORMAL  OPEN`；绿灯亮，黄灯灭；阀门指示灯亮；PA8 变高，继电器吸合。**这一步不需要按任何键。**

这条成立的前提是 EEPROM 里没有留存上一次的锁存（配置区第 12 字节为 0）。如果是第一次运行、或者上一轮结束时阀门是开着的，就会看到这个现象；如果上一轮是带着报警或远程关阀结束的，EEPROM 里留着锁存，那么预热结束后不会自动开阀——那是对的，见第 9 步。ALARMS 也会带出上一条报警的次数。

在任一终端输入 `STATUS?`（终端里直接敲，回车）：

```text
STATE=NORMAL VALVE=OPEN ALARMS=0
MQ4=640/2400 MQ7=640/2000 MQ8=640/2400
```

### 3. 预警

把 MQ-4 那一路的电位器调到 **2.41 V**（约 1920 计数）。预期：

- OLED 末行 `WARNING OPEN`，`MQ4 19xx/2400`
- 黄灯亮，绿灯灭，红灯灭
- **阀门保持打开**，继电器不动作
- 蜂鸣器不响，串口不主动推送

### 4. 报警

把 MQ-4 电位器调到 **3.01 V**（约 2400 计数）以上。预期：

- OLED 末行 `ALARM  CLOSED`，`MQ4 24xx/2400`
- 红灯亮，黄灯灭，绿灯灭
- **继电器立即释放，阀门关闭**，阀门指示灯灭
- 蜂鸣器响，**默认 5 秒后自动停**
- 参数页的 `ALARMS` 计数加一

两个终端同时自动打印一行，不需要查询：

```text
ALARM MQ4 MQ4=24xx MQ7=640 MQ8=640
```

报警持续期间记录**只写一条**。把电位器继续往上拧，不会再产生新记录。

### 5. 查历史

任一终端输入 `HISTORY?`：

```text
HISTORY 1/14
1 SEQ=1 MQ4=24xx MQ7=640 MQ8=640 ALARM=MQ4 UP=6x
```

`UP` 是报警发生时设备已运行的秒数。**没有日期时间**——板上没有 RTC，记录里存的是它确实知道的那个量，而不是伪造一个时间戳。

也可以按 KEY1 切到历史页，OLED 上看到同样的内容：`REC 1  SEQ 1`、`UP 6x s`、三路读数、`ALARM MQ4`。历史页上 KEY2/KEY3 是翻阅记录，不是改参数。

### 6. 浓度恢复，阀门保持关闭

把 MQ-4 电位器拧回 0.8 V（约 640 计数）。预期：

- 状态变成 `SAFE`（已恢复，等待确认）
- 红灯灭，黄灯亮，绿灯灭
- **阀门仍然关闭**，继电器不吸合

这一步是整个设计的重点：气体散了不等于可以重新开阀，必须人工确认。

### 7. KEY4 恢复

三路都低于安全线并**持续 3 秒**后，按 KEY4。预期：

- 状态回到 `NORMAL`，阀门重新打开，绿灯亮，黄灯灭
- 参数页 `ALARMS` 计数不变

**反向也要试一次**：再走一遍第 4 步制造报警，第 6 步把浓度调低，然后在 3 秒之内按 KEY4——应该**没有反应**。恢复条件不满足时按键必须无效，这是被主机测试覆盖的行为。

### 8. 远程关阀，以及为什么不能远程开阀

任一终端输入：

```text
VALVE CLOSE      →  OK VALVE=CLOSED
VALVE OPEN       →  ERR ONLY CLOSE
```

`VALVE CLOSE` 会让阀门关闭并锁存；`VALVE OPEN` 被明确拒绝。这是设计要求：如果链路上能开阀，锁存就形同虚设。远程关阀之后要想开阀，走的是和第 7 步完全一样的路——三路低于安全线持续 3 秒，然后按 KEY4。

关阀之后 OLED 会显示 `SAFE  CLOSED`、黄灯亮，这是正常的：软件只知道阀门被锁存了，而它同时知道当前浓度是安全的，两个事实分别显示，谁也不掩盖谁。

### 9. 掉电之后阀门仍然锁着

接第 8 步（阀门处于锁存状态），停止仿真再重新运行。**先确认第六节的 EEPROM 掉电保持这一条已经实测过。**

预期：

- 上电不自动开阀。预热 60 秒内显示 `WARMUP  CLOSED`，预热结束后进入 `SAFE  CLOSED`——阀门**始终关闭**
- 继电器不吸合，阀门指示灯灭，黄灯亮，绿灯灭
- 三路电位器都在 0.8 V（浓度是安全的），阀门照样不开
- 串口：

```text
STATUS?
STATE=SAFE VALVE=CLOSED ALARMS=1
MQ4=640/2400 MQ7=640/2000 MQ8=640/2400
```

三路都低于安全线并持续 3 秒后按 KEY4，阀门才重新打开。这一条是整个系统里最值得演示的：气体散了、电也断过了，阀门还是关着——因为它关阀的理由不因为断电而消失。

**对照实验**：把 EEPROM 里的 lockout 清掉（按 KEY4 开阀，或换一片空的 EEPROM 模型）之后重新运行，同样的浓度下应该在预热结束时自动开阀。两次的差别就是那一个字节。

### 10. 在线改参数

按 KEY1 切到 MQ-4 阈值页，用 KEY2/KEY3 改到 2500，停止操作 2 秒。预期：

- OLED 参数页 `> MQ4  TH  2500`
- `STORE OK`（若显示 `STORE FAIL`，见第六节的 I2C 上拉）

任一终端输入 `CONFIG?` 确认：

```text
TH MQ4=2500 MQ7=2000 MQ8=2400 PERIOD=100 BUZZ=5S
```

串口改参数走的是同一条校验路径，可以对照测试：

```text
SET MQ4 2600      →  OK MQ4=2600
SET PERIOD 500    →  OK PERIOD=500
SET PERIOD 255    →  ERR RANGE      （不是 10 ms 的整数倍）
SET MQ4 100       →  ERR RANGE      （低于下限 200）
SET MQ4 abc       →  ERR VALUE
SET MQ9 1000      →  ERR NAME
NONSENSE          →  ERR UNKNOWN
```

### 11. 长报文不打断采样

输入 `HISTORY?`，或在终端里连续敲几条命令。预期：

- 应答逐行出现，不会卡住
- **全程不出现 `FAULT`，阀门不会因为查询而关闭**

这一条是特意设计并验证过的：14 条记录约 750 字节，HC-05 在 9600 baud 下要 780 ms 才发得完，比采样器自己的故障超时（100 ms 周期下只有 300 ms）还长。所以应答是中断发送、每次主循环只发一行。如果演示时发现查询命令会把阀门关掉，说明这一层坏了。

### 12. 改报警蜂鸣器的响铃时长

默认 5 秒。按 KEY1 切到 `BUZZ` 那一页，用 KEY2/KEY3 逐秒调整。预期：

- `> BUZZ 5S`，按三下 KEY2 变成 `> BUZZ 8S`
- 一直按 KEY2 会停在 `> BUZZ ALWAYS`，再按不再变化——加号永远意味着「响得更久」，不会绕回 `OFF`
- 一直按 KEY3 会停在 `> BUZZ OFF`，再按不再变化
- 停手 2 秒后 `STORE OK`

串口改的是同一个字段，两个特殊档位是**词**不是数：

```text
SET BUZZER 30      →  OK BUZZ=30S
SET BUZZER ALWAYS  →  OK BUZZ=ALWAYS
SET BUZZER OFF     →  OK BUZZ=OFF
SET BUZZER 61      →  ERR RANGE     （61 是「一直响」的编码，不读作 61 秒）
SET BUZZER 256     →  ERR RANGE     （收窄成 0 就成静默关掉了，所以先判范围）
SET BUZZER FOO     →  ERR VALUE
```

然后回到第 4 步制造一次报警，确认蜂鸣器按新档位响。**设成 `ALWAYS` 时它不会自己停**，要等浓度恢复、报警解除才安静；设成 `OFF` 则完全不响，红灯和关阀不受影响。`CONFIG?` 打印出来的档位（如 `BUZZ=5S`）可以原样敲回去，秒数后的 `S` 可有可无。

## 八、故障排查

| 现象 | 先查什么 |
| --- | --- |
| 什么都不动，终端无应答 | BOOT0 是否下拉；Clock Frequency 是否为 8 MHz；HEX 路径是否正确、是否重新编译过 |
| 上电直接 `FAULT` | ADC 模型是否完成转换；PA0/PA1/PA4 上是否有电压；Clock Frequency |
| OLED 全黑 | I2C 上拉是否加了；MCU 属性里的 I2C1 引脚是否为 PB6/PB7；也见第六节（模型的可用性） |
| `STORE FAIL` 一直显示 | I2C2 上拉是否加了；24C02 模型的地址是否为 0x50 |
| 串口 2 乱码 | 终端波特率是否设成 **9600** |
| 串口 1 乱码 | 终端波特率是否设成 **115200** |
| 按键按了没反应 | 按键一端是否接 GPIO、另一端接地；GPIO 是否配了内部上拉（由固件的 `MX_GPIO_Init` 负责，不要额外加上拉） |
| 阀门在复位瞬间吸合 | PA8 的 10 kΩ 下拉是否加了 |
| 蜂鸣器一直响 | 先看档位：设成 `ALWAYS` 就一直响到报警解除，这是设置不是故障。否则固件按报警边沿计时、到点即停，若仍持续响，检查是否在反复产生新的报警边沿（读数在阈值上下抖动） |
| 浓度正常但上电不开阀 | 多半是对的：EEPROM 里留着上一次的锁存。用 `STATUS?` 看 `VALVE=CLOSED` 且 `STATE=SAFE` 即是此情形，按 KEY4 解除。若希望每次干净上电，见第六节的 EEPROM 掉电保持 |

## 九、仿真通过之后

仿真只能证明软件链路。接下来按顺序做：原理图 → PCB → 实物。PCB 采用 STM32F103C8T6 最小系统板插接方案；MQ AO 保留本文第四节的 10 k/18 k 分压；PA8 的硬件下拉必须保留。
